# CODEMAP — TigerTagSplashESP32.ino

Navigation map for the firmware's single **~12 500-line** source file. Never read
it whole; that is the entire point of this document.

**The workflow, every time:**

1. Find the section or function in the tables below.
2. `grep -n "theName" TigerTagSplashESP32/TigerTagSplashESP32.ino` — the line
   number here is a starting point, the grep is the source of truth.
3. `Read` that line ±60.
4. Make the smallest edit that does the job.
5. `bash scripts/check-codemap.sh` before you finish, and fix any drift it
   reports by updating the numbers below.

Line numbers here were regenerated mechanically against the current file and
verified by `scripts/check-codemap.sh` (0 drift). They go stale the moment
anyone inserts lines above an anchor — which is why step 2 exists.

Two gaps and two oddities in that numbering, all deliberate:

- **§12 does not exist.** It was removed in an earlier session. Renumbering
  everything after it would invalidate every `§N` cross-reference in the source
  comments and in this file, for no gain.
- **§AUDIO and §LVGL are unnumbered on purpose** — they were added after the
  numbered scheme was set, and a name is more useful than squeezing them in.
  `update_toc.sh` accepts any `§<token> — Title`, so both appear in the TOC.
- **§7 is still called "OLED DISPLAY" in the source banner.** There is no OLED
  on V3; it is a 480×320 LCD. The name is inherited from V2 and left alone here
  because it is load-bearing for cross-references — renaming it is a fine
  follow-up, but it is not a hygiene fix.
- **§8 (Cloud parsing) is 15 lines** and holds only declarations;
  `parseCloudSpoolMeta` is actually defined down in §20.

## Landmines — read the note before editing these

Hard-won knowledge that is not visible from the code itself. Each of these cost
a debugging session at least once.

| Function | What you need to know first |
|----------|------------------------------|
| `setupRFID` | RFID transport is a **build-time** choice, never runtime. Building the env that does not match the physical wiring yields firmware that finds no reader and says nothing about why. The bench-verified unit is HSU → `-e esp32s3_hsu`. The SPI-only `SPI.begin()` inside is guarded for exactly this reason: it used to claim GPIO47/48/41 before `Serial1`/`Serial2` could bind them, so the HSU build transmitted nothing at all. |
| `handleWeighWorkflow` | The removal-detected reset block captures `gRecentlyRemovedUid1`/`2` and `gRemovalDetectedMs` from `lastUID`/`lastUID2` *just before* clearing them. That is what lets a delayed RFID echo of a tag that was just lifted off be told apart from a genuinely new tag — the fix for the phantom triple-beep on spool removal. Its `WF_IDLE` branch must also keep clearing `lastUID`/`lastUID2`/`lastUIDLeft`/`lastUIDRight` once weight drops below `MIN_WEIGHT_TO_SEND_G`, or the UI stays stuck on "remove material" with an empty scale. |
| `isDuplicateRecentUid` / `isUidLatched` | The dedup window is 1.5 s and was deliberately never widened. The phantom-beep bug it once seemed related to is handled by the separate, narrower mechanism above, checked only at the `playSoundTheme()` call sites. |
| `isRapidChange` | Computes a real rate of change in g/s, independent of how often `loop()` happens to call it. The old fixed 50–100 ms gate effectively never engaged the fast filter, so every weight change crawled through the slow one. |
| `processAutoTare` | There is exactly **one** auto-tare handler: the negative-drift one (1 s sustained, plus idle/empty guard, plus 10 s cooldown). An earlier "immediate" ~250 ms handler was removed because a firm spool placement's mechanical undershoot could trigger it, taring the scale onto the item's own weight while it sat on the platform. Do not reintroduce a short-debounce variant. |
| `readWeight` | If this ever reads 0 g or inverted "no matter what", check the **sign** of raw `scale.get_units()` before touching filters or auto-tare. A swapped load-cell wire produces exactly that symptom, because the downstream `if (weight < 0) weight = 0` clamp makes a hardware polarity fault look identical to a software bug. This has happened once already. |
| `downloadUserAvatar` | **Suspected to hang the device** when given a real, valid URL. Until 2026-07-28 it had only ever run with an empty or invalid URL, so nobody noticed. Not isolated yet — read this before touching the avatar-photo feature. |
| `readInventoryContainerWeight` | Silently returns 0 on any HTTP or parse failure, with no retry. Known gap, not a bug to be surprised by. |
| `otaApply` | `firmware_url` must point at the plain `firmware.bin`. `Update.begin()`/`write()` only replace the app partition, so handing it a `firmware.factory.bin` corrupts the bootloader and partition table. |
| `applyPN532RfTuning` | Sets TX drive and RX sensitivity together via `RFConfiguration` CfgItem 0x0A, through the library's public `sendCommandCheckAck()` — no library patch needed. The 5-level table exists because the two antennas sit ~75 mm apart facing each other and cross-talk; the levels span only the low-power end, which is the range that matters for that. Default level 3. |
| `tsKeyboard` | The shift-key highlight uses an `LV_EVENT_DRAW_PART_BEGIN` callback on a specific button index, **not** `LV_STATE_CHECKED`. `LV_KEYBOARD_CTRL_BTN_FLAGS` bakes `LV_BTNMATRIX_CTRL_CHECKED` into every control key, so styling via that state lights up shift, 1# and backspace all at once, and lights them from creation regardless of actual state. |

## Parallel-file pattern — i18n

`TigerTagSplashESP32/i18n.h` holds **82 keys × 8 language blocks**
(EN/PT/FR/ES/DE/ZH/IT/PL). Adding one key means editing **all 8 blocks**, in the
same order as the enum. `bash scripts/check-i18n.sh` must exit 0 before you
compile — it discovers the language list from the file itself, so a 9th language
cannot leave the check behind.

The web UI's translations are a separate set: `data/www/locales/*.json`
(9 files, ~143 keys each, includes `pt-pt` which the firmware table does not).

## Keeping this file honest

| Command | When |
|---------|------|
| `bash scripts/update_toc.sh` | After adding, moving or renaming a `// §N — ` banner |
| `bash scripts/check-codemap.sh` | Before finishing any edit to the .ino |
| `bash scripts/check-i18n.sh` | After any edit to `i18n.h` |

All three run in CI on every push and pull request, so drift fails the build
rather than quietly accumulating. Note that they were all three broken on macOS
until this repo's first commit: two used `mapfile`/`grep -P`/`declare -A`, which
bash 3.2 and BSD grep do not have, and `check-codemap.sh` printed
"CODEMAP check PASSED" while having verified nothing at all.
