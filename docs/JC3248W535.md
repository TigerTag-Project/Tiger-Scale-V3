# Guition JC3248W535C_I_Y

Use PlatformIO environment **`jc3248w535_hsu`** for this board. It is an
ESP32-S3-WROOM-1 with 16 MB flash, 8 MB OPI PSRAM, a 320 x 480 AXS15231B QSPI
display, and capacitive touch at I2C address 0x3B. It is different from the
classic ESP32-3248S035 (ST7796/GT911) and both Waveshare boards.

This environment is source-only. The owner confirmed working display, touch,
and speaker output after USB installation; HX711 and NFC readers remain unverified.
The existing 16 MB partition table and 480 x 320 landscape UI are retained.

## Build and upload

```bash
pio run -e jc3248w535_hsu
pio run -e jc3248w535_hsu -t upload
pio run -e jc3248w535_hsu -t uploadfs
pio device monitor -b 115200
```

In VS Code, select `jc3248w535_hsu` under PlatformIO Project Tasks. Upload both
firmware and filesystem for the initial installation. The project default
environment remains the reference Waveshare build.

## Onboard connections

| Function | GPIO |
|---|---|
| LCD QSPI CS / clock | 45 / 47 |
| LCD QSPI D0 / D1 / D2 / D3 | 21 / 48 / 40 / 39 |
| Backlight (active high) | 1 |
| Touch SDA / SCL | 4 / 8 |
| Speaker I2S BCLK / LRCK / data | 42 / 2 / 41 |

Touch uses the AXS15231B's 11-byte request and 8-byte response. No external LCD
reset or ES8311 codec initialization is used. The speaker amplifier takes I2S
directly; volume is applied to the generated samples.

The board's battery circuit is not an AXP2101. Battery percentage, charging
status, and software power-off are unavailable in this environment. Use the
board's physical battery button. GPIO5 is connected to battery sensing and
GPIO46 is input-only; neither is assigned to an external peripheral here.

## HX711 and PN532 wiring

These assignments use the exposed connectors without sharing display, touch,
audio, USB, flash, or PSRAM pins. They are new assignments for this board;
do not copy the Waveshare wiring diagram.

| Peripheral signal | ESP32 GPIO | Connector |
|---|---|---|
| HX711 DOUT / DT | 17 | 4-pin IO port |
| HX711 SCK / CLK | 18 | 4-pin IO port |
| Right PN532 TXD -> ESP32 RX | 6 | 8-pin IO port |
| Right PN532 RXD <- ESP32 TX | 7 | 8-pin IO port |
| Right PN532 RSTPD_N input (optional; not RSTO) | 9 | 8-pin IO port |
| Left PN532 TXD -> ESP32 RX | 15 | 8-pin IO port |
| Left PN532 RXD <- ESP32 TX | 16 | 8-pin IO port |
| Left PN532 RSTPD_N input (optional; not RSTO) | 14 | 8-pin IO port |

The supplier schematic labels the 8-pin port P2, with pins 1 through 8 mapped
to GPIO5, 6, 7, 15, 16, 46, 9, and 14 respectively. P3/P4 are alternate 4-pin
connectors carrying GND, 3.3 V, GPIO17, and GPIO18. Confirm connector orientation
against the diagram before wiring. The 8-pin port's GPIO5 pin is not a 5 V supply.

Use a common ground and 3.3 V logic. Power each module according to its own
specification; the 4-pin IO port provides 3.3 V. Set each PN532 to UART/HSU
(Elechouse V3: both mode switches OFF). HSU needs no SS/CS connection. Reader
1 uses Serial1 at 115200 baud; reader 2 uses Serial2 at 115200 baud. Use the
TXD/RXD labels on the back of an Elechouse V3: its front SDA/SCL labels refer
to the same pins in I2C mode. Power-cycle the readers after changing modes.

Each reader needs VCC, common GND, TXD, and RXD. A reset wire is optional in
HSU mode. Only connect GPIO9/14 if the module exposes a genuine `RSTPD_N`
reset input. Leave `RSTO`/`RSTOUT_N` unconnected: it is a reset output, not
the input the firmware drives. Without a reset input connection, hardware
reset recovery and power-down isolation of the readers are unavailable.
With one reader, use the right-reader connections; the firmware detects which
readers respond.

Connect the HX711 before taring or calibrating. Its unwired data input can
float, produce false readings, or leave the existing blocking tare routine
waiting indefinitely. Display/touch bring-up can be checked without the readers.

## Updates and verification

The firmware reports board ID `jc3248w535`. Automatic update lookup requires
`boards["jc3248w535"]` in the release manifest and never falls back to a
Waveshare image. No image for this board is currently published by this project;
use USB uploads. This environment is included in CI and `scripts/verify.sh --all`.

After uploading, check the serial log for `[LCD] begin OK w=480 h=320`, a touch
probe ACK at 0x3B, and `[LVGL] init OK`. Test taps in all four corners, brightness,
speaker volume, each NFC reader, and load-cell calibration on the device.
Compilation alone cannot verify these behaviors.
