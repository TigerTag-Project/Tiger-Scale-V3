# v3.7.0

Mostly invisible on the scale itself: this release is about the apps that talk
to it. Tiger Studio Manager can finally read what it asks the scale, and one
request now returns everything.

## Fixed

- **Apps could not read the scale's answers.** A browser-based app — Tiger
  Studio Manager among them — could send a command and have the scale carry it
  out, but never see the reply. Its tare button reported success whether the
  scale had tared or was unplugged. The scale now answers properly.
- **Two diagnostic endpoints had never worked.** `/api/session` and
  `/api/history` returned "not found" on every scale ever shipped. They report
  the weighing in progress and a short event log.

## Added

- **One request returns the whole picture.** `/api/status` now includes the
  battery level, whether a battery is fitted, whether it is charging, whether the
  scale is on USB or on the cell, the screen state and the WiFi signal — the same
  values the app already receives live. An app that loses its live connection can
  resynchronise in a single call.

## Changed

- The scale keeps refusing the commands that reconfigure it — calibration,
  account, updates — to anything coming from a web page. Reading its state and
  taring it are open; changing what it is, is not. The local API has no password,
  and that line is what stands in for one.

## Known issues

- On-tag metadata reads still fall back to the cached values; a spool never
  seen before may show no brand or material.

## Updating

- **Over the air** from **Settings > Update** — keeps your WiFi credentials,
  TigerTag session and calibration.
- Or from the [web installer](https://tigertag-project.github.io/Tiger-Scale-V3/),
  which always serves the current release.
