# v3.7.6

A small release about the screen telling the truth in your language, and about
the project's own checks covering what they claim to cover.

## Fixed

- **The RFID screen said LECTEURS in every language.** Settings > RFID labelled
  its reader pills with a French word written directly into the code, so an
  English scale showed it too, and so did a Chinese one. It now reads from the
  translation table like every other label on that screen — "RFID READERS",
  "LECTEURS RFID", "CZYTNIKI RFID" and the six others.

## Removed

- **A bring-up test screen that was still shipping.** A label reading "LVGL OK"
  and a tap counter, written while the LVGL bridge was being brought up, had
  been in every image since — unreachable, but built into all of them.

## Under the hood

Nothing here changes what the scale does; it changes what the project can no
longer get wrong.

- **A word on the panel now has to come from the translation table.** A check
  fails the build if a string literal carrying a word is handed to a screen
  label. That is the class of bug the RFID screen was, and it was invisible in a
  diff, in a build, and in a 16 000-line file.
- **Documented device names have to match the one the firmware builds.** Two
  documents told you to open `tigerscale.local`, which resolves to nothing: the
  real name carries four hex digits from the MAC address. A check compares the
  documentation against the code that builds the name.
- **Generated files have to agree with their own declarations.** The bitmap
  headers and the font faces each record what they contain; nothing was
  verifying that they still do, and the font check trusts exactly that record.
- **The summary written for language models is checked like code.** `llms.txt`
  had gone five weeks naming the wrong build environment as the verified one —
  the single most expensive mistake this project has, recommended by the one
  file an AI assistant reads first. It is now checked against the repository at
  every change, and it has to be re-read and re-affirmed at every version.
- **The release gate runs every check.** It named three guard scripts and went
  on naming three while the suite grew to eleven, so a release could be
  published having verified a third of what a bench check covers. It now runs
  the same one command a developer runs.
